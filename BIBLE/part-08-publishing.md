### 8.3 Caddy configuration

The implementer locates the Caddyfile used by the "Websites ON" launcher (look under /home/nir/strulovitz-website/hosting/), confirms it is tracked in the website's git repo, and adds inside the strulovitz.org site block, before the existing file_server or root directives:

```
handle_path /crystal-balls/* {
    root * /home/nir/crystal-balls/public
    file_server
    header Cache-Control "public, max-age=300"
}
redir /crystal-balls /crystal-balls/ permanent
```

handle_path strips the /crystal-balls prefix, so public/index.html answers at /crystal-balls/ and public/data/index.json at /crystal-balls/data/index.json; the page's relative paths work unchanged. Validate with caddy validate --config [path], commit and push the Caddyfile in the website repo, then on the other computer git pull in the website repo. If Caddy is running, reload it (caddy reload --config [path] or restart through the launcher). If the Caddyfile is generated by a script rather than hand-edited, put the block in whatever template that script reads, and say so to Nir.

Fallback only if the Caddy approach is impossible: find the website's build script, add a step that copies /home/nir/crystal-balls/public/ into the export as crystal-balls/, and document it in this file.

### 8.4 scripts/publish.sh

```bash
#!/usr/bin/env bash
# Crystal Balls: publish the latest data to the website. Called by the desktop icon.
set -uo pipefail
REPO="/home/nir/crystal-balls"
cd "$REPO"
if [ "${1:-}" = "--in-terminal" ]; then
  # same terminal re-launch block as run_round.sh, calling publish.sh
  ...
fi
say() { echo "[$(date +%H:%M:%S)] $*"; }
say "Pulling latest from GitHub..."
git pull --rebase || { say "git pull failed."; exit 1; }
say "Building site data..."
"$REPO/.venv/bin/python" pipeline/build_site_data.py
say "Updating the public folder..."
mkdir -p public
rsync -a --delete --exclude data site/ public/
mkdir -p public/data/rounds
cp data/index.json data/meta.json data/scorecard.json public/data/
for R in data/rounds/*/; do
  if grep -q '"status": "complete"' "$R/round.json"; then
    N="$(basename "$R")"; mkdir -p "public/data/rounds/$N"
    rsync -a --delete --include='bundle.json' --include='round.json' --include='countries/***' --exclude='*' "$R" "public/data/rounds/$N/"
  fi
done
if pgrep -x caddy >/dev/null; then
  say "Websites are ON. The new round is live at https://www.strulovitz.org/crystal-balls/"
else
  say "Websites are OFF right now. The page will be live next time you turn the websites on."
fi
say "Publish done."
```

Because Caddy serves files directly from public/, publishing needs no restart. The 300-second cache header means visitors see a new round within five minutes.

### 8.9 Troubleshooting, in plain words for Nir

The icon does nothing: right-click it, choose "Allow Launching" (GNOME) or make sure it is executable (chmod +x ~/Desktop/*.desktop).
"The model server is not running": start Unsloth Studio or Ollama, load the model, run the icon again.
"git pull failed": open OpenCode in /home/nir/crystal-balls and say "resolve the git conflict, keeping the newest round files".
The round stopped halfway (power, sleep): double-click the icon again; it continues.
Some countries failed: the summary prints the retry command; or open OpenCode and say "retry the failed countries of today's round".
The page shows "No forecast rounds published yet": run the Publish icon; make sure public/data/index.json exists.
Wrong or silly emojis: edit config/emoji_vocabulary.json meanings, or the prompts; never edit stored rounds.
Switching to OpenRouter for a stronger model: in settings.env set LLM_BASE_URL=https://openrouter.ai/api/v1, LLM_MODEL to the model id, LLM_API_KEY to the key, UNCENSORED_PREAMBLE=false, LLM_CONTEXT_BUDGET=60000.
